# 0001 — 색 선언의 의미는 프로퍼티가 정한다

- **Status:** **Accepted — 2026-08-10**, 사용자 판정 (#71). 2026-08-06 에 Proposed 로 작성.
- **Supersedes:** 없음. 이 저장소의 첫 결정 기록.
- **Conformance items:** #62, #63, #64. 완료: #69 (PR #70).

## 수락 — 사건으로서

**이것은 유도가 아니라 제품 판정이고, 되돌릴 수 있는 사람은 사용자뿐입니다.** 더 나은 논증을 들고 오는 나중의 적대적 검토가 이 결정을 다시 열지 않습니다. 그래서 무엇을 보고 골랐는지를 여기 적어둡니다.

사용자에게 제시된 것:

- 규칙 둘(R1·R2)과 그로부터 나오는 (프로퍼티 × 선언 상태) 격자 전체.
- 수락의 **행동적 귀결**: 못 읽는 `stop-color` 가 오늘의 예외에서 검정으로 바뀐다는 것 — `#64` 가 들고 있는 변경이며, 사용자 눈에 보이는 변화입니다.
- 일부러 유도와 다르게 둔 것 하나(대상 없는 `url(#…)` 에서 던지는 것)와 그 이유.
- **알려진 구멍 하나**: 아래 "유효 조건" 의 첫 항목 — `fill` 열 전체가 상류 루트의 `fill="none"` 에 매달려 있는데 래스터라이저는 루트를 읽지 않으므로, 그날이 오면 아무것도 안 던지고 조용히 틀립니다.

선택지 셋이 제시됐습니다: 그대로 수락 / 루트 가드를 `#62` 의 AC 로 붙이고 수락 / 먼저 문서를 검증(grilling). **사용자는 "그대로 수락" 을 골랐습니다.**

따라서 **루트 가드는 만들어지지 않았고, 이 기록의 유효 조건으로 남습니다.** 침묵하는 결함이 아니라 보고 넘긴 결함입니다 — 그 구분이 이 문단의 목적입니다. 필요해지는 날의 자리는 `#62` 이고, 신호는 어떤 variant 의 루트가 `fill` 을 색으로 선언하는 것입니다.

## 왜 이슈가 아니라 기록인가

이슈 하나는 결정 하나를 담습니다. 여기 있는 것은 결정들을 **가로지르는 규칙**이라 구조적으로 이슈에 안 들어가고, doc-comment 에 적으면 코드의 한 가지에만 못 박힙니다.

theflow 의 승격 트리거가 둘 발동해서 올라왔습니다:

1. **이미 결정한 참가자들을 다른 조합으로 또 결정하고 있었습니다.** 축이 둘 — 프로퍼티(`fill` / `stroke` / `stop-color`)와 선언 상태(부재 / `none` / `url(#…)` / 색 / 못 읽음). 격자의 칸을 #69 가 몇 개, #64 가 몇 개씩 따로 정하는 중이었고, 매번 앞 결정을 재해석했습니다.
2. **저장소 안의 두 기록이 서로 반대를 말했습니다.** hidden-state **#20** 은 "래스터라이저는 `null` 을 돌려주고 안 그린다" 라고 단언하고, **#44** 는 "`sunset` 은 던진다, #20 은 더 이상 사실이 아니다 — needs a ruling" 이라고 몇 줄 아래에 적혀 있습니다.

## 결정 — 규칙은 둘이고, 나머지는 전부 유도된다

**표를 외우지 마십시오. 아래 두 규칙에서 모든 칸이 나옵니다.**

### R1 — 어떤 토큰이 유효한지는 그 프로퍼티의 문법이 정한다

우리 파서가 읽을 수 있느냐가 아닙니다. SVG 1.1 원문:

- **§11.2** — `fill` 과 `stroke` 는 `<paint>` 를 받습니다:
  `none | currentColor | <color> [<icccolor>] | <funciri> [ none | currentColor | <color> [<icccolor>] ] | inherit`.
  `none` 은 첫 대안이고 정의는 *"Indicates that no paint is applied"*.
- **§13.2.4** — `stop-color` 는 `currentColor | <color> <icccolor> | inherit` 를 받습니다.
  **`none` 도 `<funciri>` 도 이 문법에 없습니다.**

### R2 — 무효한 선언은 무시되고, 그 자리는 상속값 또는 초깃값이 채운다

- **CSS 2.1 §4.2** — *"User agents must **ignore** a declaration with an illegal value."*
- **CSS 2.1 §6.1.1** — 무시된 뒤 지정값을 정하는 순서: (a) cascade 에 값이 있으면 그것, (b) **상속되는 프로퍼티이고 루트가 아니면 부모의 계산값**, (c) 아니면 **초깃값**.

세 프로퍼티의 해당 사실 (§11.3, §11.4, §13.2.4):

| 프로퍼티 | 문법 | 상속 | 초깃값 |
|---|---|---|---|
| `fill` | `<paint>` | **예** | `black` |
| `stroke` | `<paint>` | **예** | `none` |
| `stop-color` | `currentColor \| <color> <icccolor> \| inherit` | **아니오** | `black` |

**이 두 규칙이 #64 가 Chrome 에서 잰 표를 한 칸도 안 빼고 재현합니다.** `fill` 과 `stop-color` 가 다르게 구는 것은 우리가 정한 예외가 아니라 *상속 여부가 다른 한 규칙의 두 결과*입니다.

## 유도

각 칸은 규칙에서 나온 것이고, 실측은 유도의 **검산**이지 근거가 아닙니다.

| 선언 | `fill` | `stroke` | `stop-color` |
|---|---|---|---|
| **부재** | R2(b): 상속 → 루트의 `none` → **안 그림** | R2(b/c): 아무 조상도 선언 안 함 → 초깃값 `none` → **안 그림** | R2(c): 상속 안 함 → 초깃값 → **검정** |
| **`none`** | R1: 유효 → **안 그림** | R1: 유효 → **안 그림** | R1: 문법 밖 → R2(c) → **검정** |
| **`url(#…)`**, 대상 있음 | R1: 그 paint server | R1: 그 paint server | R1: 문법 밖 → R2(c) → **검정** |
| **`url(#…)`**, 대상 없음 | §11.2 는 "document is in error"; CSS `<url>` 의 used value 는 `none` → **안 그림** | 같음 | 문법 밖 → **검정** |
| **읽은 `<color>`** | 그 색 | 그 색 | 그 색 |
| **진짜 무효** (`zzz`, `""`) | R2(b): 상속된 `none` → **안 그림** | R2(c) → **안 그림** | R2(c) → **검정** |

**검산 — #64 의 Chrome 실측표와 대조하면 네 행이 전부 맞습니다:** `zzz` (안 그림 / 검정), `""` (안 그림 / 검정), `none` (안 그림 / 검정), `transparent` (양쪽 투명 — `transparent` 는 유효한 `<color>` 이므로 무효값 규칙이 아니라 "읽은 색" 행입니다). 부재는 #8·#39 의 빈 팔레트 실측이 검산합니다 — 다섯 variant 는 안 그리고 `sunset` 만 검정 원반.

### 유도가 곧바로 정하는 것 하나: 티켓 순서

**"우리가 못 읽는 값" 은 "무효한 값" 이 아닙니다.** `red`, `#F00`, `rgb(…)`, `#RRGGBBAA`, `transparent` 는 브라우저에게 전부 **읽은 색** 행이지 무효 행이 아닙니다. 여기에 R2 를 적용하면 `red` 가 `stop-color` 에서 검정으로 그려집니다 — 지금보다 나쁩니다.

그래서 **#62 → #63 → #64 의 순서는 이 기록에서 유도됩니다.** 표기를 다 배우기 전에는 "무효" 의 외연이 정해지지 않고, 정해지지 않은 것에 R2 를 적용할 수 없습니다. 순서는 편의가 아니라 규칙의 결과입니다.

## 유효 조건 — 이게 무너지면 기록이 먼저 깨진다

- **`fill` 칸 전부가 루트의 `<svg fill="none">` 에 매달려 있습니다.** R2(b) 가 상속값을 쓰기 때문이고, 그 상속값을 놓는 것이 루트입니다. 600 렌더 전부에서 참이며(#8, #17) 네 variant 가 그 속성을 직접 씁니다. **어떤 variant 의 루트가 색을 선언하는 날 `fill` 열이 통째로 뒤집힙니다** — 부재도, 무효도, 그 색으로 칠해집니다. 그리고 래스터라이저는 지금 **루트를 읽지 않습니다**(`_containerAttributes` 의 허용 목록에만 있음). 즉 그날 아무것도 안 던지고 조용히 틀립니다.
- **대소문자와 공백.** CSS 키워드는 ASCII 대소문자 무관이고 앞뒤 공백을 허용합니다. 우리는 `none` 을 정확 일치로만 봅니다(#69). 오늘은 무해합니다 — `NONE` 도 "못 읽음" 으로 떨어져 같은 답이 나오고, 상류는 정확히 `none` 만 씁니다. **이 씬을 쓰는 것이 이 패키지 자신의 emitter 뿐인 동안** 유효하며, 느슨한 일치가 필요해지면 #63 이 그 자리입니다.
- **`currentColor` 와 `inherit`.** 문법에는 셋 다 있고 상류는 어느 것도 쓰지 않습니다. 유도는 이미 정해져 있습니다(`color` 를 아무도 설정하지 않으므로 `currentColor` 는 초깃값 검정) — 다만 **실측되지 않았습니다.** 나타나면 #63 에서 재고 넣습니다.

## 유도와 일부러 다른 것 하나

**대상 없는 `url(#…)` 에서 우리는 던집니다.** 유도상 답은 "안 그림" 이고 Chrome 실측도 `0,0,0,0` 입니다(#43). 그런데도 던지는 이유는 색 규칙이 아니라 **관측 가능성**입니다: 백지 아바타는 "페인트를 아예 안 읽은 버그" 와 구분이 안 되고, 그 버그는 #40 이전에 `sunset` 전체에서 조용히 일어났습니다.

**이것은 유도가 아니라 결정입니다.** 더 나은 유도가 나와도 뒤집히지 않고, 사람이 뒤집습니다.

## 이 기록이 오늘의 코드와 어긋나는 곳

기록은 기존 테스트로 검산합니다. 재현하는 것은 증거이고, 어긋나는 것은 **발견**입니다 — 조용히 뒤집지 않습니다.

- **재현(증거):** 빈 팔레트에서 `sunset` 이 검정 원반(#39), 부재한 `fill` 이 안 그림(#17), `fill="none"` 이 안 그림(#69), dangling 참조가 거부됨(#40).
- **어긋남(발견) ①:** 못 읽는 `stop-color` 에서 오늘 우리는 **예외를 던집니다.** 유도상 답은 검정입니다. **#64 가 이미 들고 있는 변경이고 여기서 뒤집지 않습니다.** hidden-state #44 의 "needs a ruling" 이 묻던 것이 이것이고, 답은 "#20 에 갈라짐을 적는다" 도 "둘을 통일한다" 도 아니라 **둘 다 한 규칙에서 나오며 오늘의 throw 가 임시**라는 것입니다.
- **어긋남(발견) ②:** `fill` 의 "못 읽음 → 안 그림" 은 **답은 맞고 이유가 다릅니다.** 우리는 "못 읽어서 안 그림" 이고 브라우저는 "무시하고 상속된 `none`" 입니다. 위의 유효 조건이 무너지는 날 두 답이 갈립니다.

## 기각한 대안

- **프로퍼티마다 답의 표를 손으로 적어둔다.** 그게 지금까지 하던 것이고, 승격의 이유입니다. 다음 조합은 또 새 결정이 되고 앞의 결정을 재해석합니다.
- **`fill` 과 `stop-color` 를 통일한다** (hidden-state #44 가 제시한 두 선택지 중 하나). **기각** — 명세가 둘을 다르게 정의하고(상속 여부와 문법이 모두 다름), 브라우저 실측도 다릅니다. 통일하면 상류를 재현하지 못합니다.
- **못 읽는 값을 전부 무효로 취급한다.** 기각 — `red` 를 `stop-color` 에서 검정으로 그리게 되고, 이는 안 그리는 지금보다 나쁩니다.

## 이 기록이 정하지 않는 것

- **색 표기 자체의 파싱.** 무엇이 `<color>` 인지는 CSS 가 정하고 #62/#63 이 구현합니다. 이 기록은 "읽은 색" 이라는 칸이 있다는 것까지만 말합니다.
- **`_readMask` 의 `fill != '#FFFFFF'` 검사.** 그것은 "마스크가 상류가 쓰는 그 흰색으로 칠해졌는가" 라는 **바이트 동일성** 질문이지 색 질문이 아닙니다. 일부러 이 어휘 밖에 둡니다.
- **팔레트가 소비자 정책이라는 것** — 그건 `CLAUDE.md` 의 경계 규칙이고 여기서 다시 정하지 않습니다.

## 새 프로퍼티가 오면

`flood-color`, `lighting-color`, `color` 같은 것이 나중에 들어오면 **표에 행을 추가하지 말고** R1 + R2 로 유도하십시오. 필요한 것은 세 가지 사실뿐입니다: 문법, 상속 여부, 초깃값. 셋 다 명세에 있습니다.
