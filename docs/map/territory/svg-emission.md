# svg-emission

## What it is
The Layer-2 byte-parity surface: `emitSvg` serialises a scene
([scene-model](scene-model.md)) into exactly the string upstream's React
component produces under `renderToStaticMarkup`. It is what `boringAvatarSvg`
returns ([public-svg-surface](public-svg-surface.md)), and the bar is byte
equality against `test/fixtures/<selector>/svg.json`. Every detail here is a
measurement, not a style choice.

## Governing decisions
**None** as ADR. One maintainer ruling bounds what the bytes may differ in: the
generated-ids ruling (2026-08-13, extended by #45) — every selector emits the
pre-`useId()` literal mask and filter ids — held in full in
[version-selectors](version-selectors.md). The one other intended byte
difference, `sunset`'s percent-encoded gradient reference (S-1), is made by the
variant builder, not here ([sunset](sunset.md),
[upstream-divergences](../aggregate/upstream-divergences.md)).

## Design model
From the source and measurements over the fixture (no record). React's
serialisation details (hidden-state #19):

- **No self-closing tags.** Every element is an open/close pair,
  `<rect …></rect>`, even with no children. Measured at HEAD: zero `/>` across
  all 2,094 documents in the three committed fixtures (580 `renders` + 58
  `squareRenders` per selector, 120 `titleRenders` each for `v1_7_0` and
  `v1_10_1`). *(The doc-comment and the retired `theflow.md` say "480 renders" —
  the count from before `marble` was ported; the claim held then and holds
  now.)*
- **No whitespace between elements.** React emits no indentation or newlines.
- **Attribute order is the node's**, written as `name="value"` in list order;
  values are `SvgAttribute.formattedValue` — `jsNum` for numbers, React's
  escaping for strings ([scene-model](scene-model.md)).
- **Text content** (`<title>` only) is escaped with the same function as
  attribute values; `'` → `&#x27;`.
- **Ids are whatever the builder wrote.** Every byte gate normalises
  `id="…"`, `url(#…)` and `mask="…"` on both sides, because upstream's
  `useId()` ids have no fixed bytes; so the literal ids this layer emits are
  pinned only by raw assertions (`the raw literals this port emits on the
  v1_10_1 path`, `sunset`'s `derivedIdentifiers`).

## Code

- `lib/src/svg/emitter.dart — _write`
- Tests: `test/svg_emitter_test.dart` — group `round-trip over every render

  really covers all six variants`), `the traps this layer has, pinned

  fixture sweeps through the public function; `test/fixtures_test.dart — every
  rendered entry is a complete svg element`, `generated ids are normalised
  away, but <title> is not`.

## Reference behaviour
- `test/fixtures/<selector>/svg.json` — `renderToStaticMarkup` output from the
  real npm package, generated by [parity-harness](parity-harness.md)
  (`tool/parity/dump.mjs`); `v1_6_1` from 1.6.1, `v1_7_0` from 1.7.0, `v1_10_1`
  from 1.10.1.
- The round-trip test parses each upstream document and re-emits it, so the
  emitter is checked against upstream's own strings independently of any
  builder.
- Pixel-level agreement of these bytes in a real browser:
  [crosscheck](crosscheck.md) (1,200 renders per selector, upstream's documents
  and ours through one Chrome).

## Cross-cutting invariants
- [frozen-selector-output](../invariant/frozen-selector-output.md) — the bytes
  this function produces for a shipped selector are the contract.

## Blast radius
- [public-svg-surface](public-svg-surface.md) — its return value is this
  function's output; any serialisation change is a byte change for every
  caller of every shipped selector.
- [crosscheck](crosscheck.md), [calibration](calibration.md) — both feed
  `emitSvg` output to Chrome as the reference input; they assume these bytes
  are what upstream would hand the browser.

## Known holes / open
- The emitter's doc-comment says "480 renders"; stale count (see Design model).
- Byte gates are id-blind by construction; an id is pinned only where a raw
  assertion exists: the per-variant parity tests read the `v1_6_1` fixture's
  `maskIdentifiers` (`pixel`, `ring`, `beam`, `bauhaus`) and
  `derivedIdentifiers` (`marble`, `sunset`), and `v1_10_1_parity_test.dart`
  checks `pixel`'s and `marble`'s literals on the `v1_10_1` path. Nothing pins
  ids on the `v1_7_0` path, or for the other four variants on `v1_10_1`. That
  is safe only while no builder except `pixel` receives version information.
